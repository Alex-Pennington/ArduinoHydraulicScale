# PLC #4 — MCP3421 loop ADC, LCD2004A display, discrete buttons

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move PLC #4's 4-20 mA loop onto an MCP3421 with its own voltage reference, replace the 16x2 parallel LCD with a 20x4 I2C one, and replace the shield's resistor-ladder keypad with discrete buttons.

**Architecture:** Three devices on the Qwiic / `Wire1` bus, which this board does not currently use, so no header pin is contended. Milliamps stay the source of truth and every count derives from `BURDEN_OHMS` and the MCP3421's reference — changing two hardware constants moves every threshold, which is the property that made the previous swap safe.

**Tech Stack:** C++17, Arduino framework, UNO R4 WiFi. Built with `arduino-cli` via `tools/build-check.sh`. Host arithmetic checks with `g++`.

**Spec:** `docs/superpowers/specs/2026-09-16-mcp3421-lcd2004-design.md`. Background: `notes/2026-09-13-4-20ma-loop-decisions.md` and `MA-LOOP-DESIGN.md`.

## THE DATASHEET CORRECTION — read before Task 2

`LogSplitter_Monitor` is the prior art and its driver is worth porting, **but two constants in its `include/mcp3421_sensor.h` are INVERTED against Microchip DS22003E.** Verified against the datasheet on 2026-09-16:

| field | datasheet DS22003E | that header says | |
|---|---|---|---|
| `RDY` when reading | **0 = latest result is ready**; 1 = not updated since last read | "0 = conversion in progress, 1 = conversion complete" | **INVERTED** |
| `O/C` bit 4 | **1 = Continuous (default)**; 0 = One-Shot | `CONTINUOUS = 0x00`, `ONE_SHOT = 0x10` | **INVERTED** |
| `S1-S0` = `01` | 60 SPS, 14 bits | `0x04` | correct |
| `G1-G0` = `00` | gain x1 | `0x00` | correct |

Datasheet §5.1.1: *"RDY bit = 0 means the latest conversion result is ready. RDY bit = 1 means the conversion result is not updated since the last reading."* And bit 4: *"1 = Continuous Conversion Mode (Default)."*

**Port the structure, not those two values.** A driver carrying them runs one-shot while believing it is continuous, and accepts only stale samples.

```cpp
// ---------------------------------------------------------------------------
// The loop is read by an MCP3421 on Wire1 (Qwiic), NOT by the R4's internal ADC.
//
// WHY, AND IT IS NOT THE RESOLUTION -- the resolution is the same 14 bits. The
// MCP3421 carries its OWN 2.048 V reference, so the board's supply rail leaves
// the measurement entirely. The retired ratiometric transducer tracked AVCC and
// its error cancelled; a burden resistor does not cancel, and the internal ADC
// references a rail that on USB sits anywhere in 4.75-5.25 V -- up to +/-5% gain
// error against a transmitter rated +/-1.0% FS. That was issue #4, and this
// closes it by construction rather than by someone metering the rail.
//
// 14 BITS IS A RATE CHOICE. The MCP3421 trades resolution against sample rate:
// 18-bit is 3.75 SPS, 16-bit 15 SPS, 14-bit 60 SPS. This firmware samples every
// SAMPLE_SPACING_MS = 50 ms, so 18-bit would take 2.7 s for one 10-sample
// reading and the scale would visibly lag the load. 14-bit is still 43.5x finer
// than the sensor's own +/-30 psi. DO NOT "UPGRADE" THIS.
//
// WHY 68 OHM: the constraint is I * R <= 2.048 V. The binding current is the
// 29.7 mA hard-over PLC #3 actually METERED (playbook s10), giving R <= 68.9,
// so 68 is the largest E24 value. Same rule that picked 150 ohm against a 5 V
// rail. THE OLD 150 OHM CANNOT BE USED HERE -- 2.048/150 clips at 13.65 mA,
// below the 20 mA span end.
//
// Burden tolerance is still a direct gain term: 0.1%, <=25 ppm/degC.
// ---------------------------------------------------------------------------
constexpr float BURDEN_OHMS      = 68.0f;
constexpr float MCP3421_VREF_V   = 2.048f;
constexpr int   MCP3421_BITS     = 14;
constexpr float MCP3421_LSB_V    = 2.0f * MCP3421_VREF_V / (float)(1 << MCP3421_BITS);
constexpr int   MCP3421_MAX_CODE = (1 << (MCP3421_BITS - 1)) - 1;   // 8191

constexpr int mAToCounts(float mA) {
  return (int)(mA * BURDEN_OHMS / 1000.0f / MCP3421_LSB_V + 0.5f);
}
```

- [ ] **Step 1: Write the header**

```cpp
#pragma once
#include <Arduino.h>
#include <Wire.h>
#include "loop_scaling.h"

// ---------------------------------------------------------------------------
// MCP3421 18-bit delta-sigma ADC, used here at 14-bit, on Wire1 (Qwiic).
//
// TWO CONSTANTS HERE ARE INVERTED IN LogSplitter_Monitor's version of this
// driver. Verified against Microchip DS22003E on 2026-09-16:
//   RDY when READING:  0 = latest result IS ready; 1 = not updated since the
//                      last read. That sibling header says the opposite.
//   O/C bit 4:         1 = Continuous (default); 0 = One-Shot. That sibling
//                      enum says the opposite.
// A driver carrying those runs one-shot believing it is continuous, and accepts
// only stale samples. Do not "restore" them.
//
// Config byte 0x14 = O/C 1 (continuous) | S1-S0 01 (60 SPS, 14-bit) | G1-G0 00 (x1).
// ---------------------------------------------------------------------------
constexpr uint8_t MCP3421_ADDR    = 0x68;
constexpr uint8_t MCP3421_CONFIG  = 0x14;
constexpr uint8_t MCP3421_RDY_BIT = 0x80;

inline uint32_t &mcpFailCountRef() { static uint32_t n = 0; return n; }
inline uint32_t  mcpFailCount()    { return mcpFailCountRef(); }

inline bool mcpBegin() {
  Wire1.begin();
  Wire1.beginTransmission(MCP3421_ADDR);
  Wire1.write(MCP3421_CONFIG);
  return Wire1.endTransmission() == 0;
}

// Returns TRUE only for a FRESH conversion. A bus failure or a not-ready sample
// returns false and leaves countsOut untouched.
//
// A FAILED READ IS NOT ZERO COUNTS. Zero counts is LOOP_DEAD -- an affirmative
// statement that the loop is open. Conflating them would publish a confident
// "no sensor" from a loose Qwiic connector, which is the plausible-wrong-answer
// failure this machine's whole history is about.
inline bool mcpRead(int &countsOut) {
  if (Wire1.requestFrom((uint8_t)MCP3421_ADDR, (uint8_t)3) != 3) {
    mcpFailCountRef()++;
    return false;
  }
  uint8_t hi  = Wire1.read();
  uint8_t lo  = Wire1.read();
  uint8_t cfg = Wire1.read();

  if (cfg & MCP3421_RDY_BIT) return false;   // RDY=1 -> stale, not a failure

  int16_t raw = (int16_t)(((uint16_t)hi << 8) | lo);
  raw = (int16_t)(raw << 2) >> 2;            // sign-extend the 14-bit result
  countsOut = (int)raw;
  return true;
}
```

```cpp
#pragma once
#include <Arduino.h>
#include <Wire.h>

// LCD2004A, 20x4, PCF8574 I2C backpack at 0x27, on Wire1 (Qwiic).
// Direct I2C rather than LiquidCrystal_I2C, matching LogSplitter_Monitor, which
// runs this display on this board.
//
// BACKPACK LEVELS ARE NOT VERIFIED HERE. These modules are typically 5 V parts
// and Qwiic is a 3.3 V bus. I2C is open-drain so it generally works and the
// sibling runs exactly this combination -- but that is proven on another
// machine, not measured on this one.
constexpr uint8_t LCD_ADDR = 0x27;
constexpr uint8_t LCD_COLS = 20;

inline void lcdPulse(uint8_t v) {
  Wire1.beginTransmission(LCD_ADDR); Wire1.write(v | 0x04); Wire1.endTransmission();
  delayMicroseconds(1);
  Wire1.beginTransmission(LCD_ADDR); Wire1.write(v & ~0x04); Wire1.endTransmission();
  delayMicroseconds(50);
}

inline void lcdSend(uint8_t value, uint8_t mode) {
  uint8_t backlight = 0x08;
  lcdPulse((value & 0xF0) | mode | backlight);
  lcdPulse(((value << 4) & 0xF0) | mode | backlight);
}

inline void lcdCmd(uint8_t c)  { lcdSend(c, 0x00); }
inline void lcdData(uint8_t c) { lcdSend(c, 0x01); }

inline void lcdBegin() {
  Wire1.begin();
  delay(50);
  lcdPulse(0x30); delay(5);
  lcdPulse(0x30); delayMicroseconds(150);
  lcdPulse(0x30); delayMicroseconds(150);
  lcdPulse(0x20); delayMicroseconds(150);   // 4-bit mode
  lcdCmd(0x28);                             // 4-bit, 2-line mode, 5x8
  lcdCmd(0x0C);                             // display on, cursor off
  lcdCmd(0x01); delay(2);                   // clear
  lcdCmd(0x06);                             // entry mode, increment
}

// Row start addresses for a 20x4: rows 2 and 3 continue rows 0 and 1.
inline void lcdLine(uint8_t row, const char *text) {
  static const uint8_t base[4] = { 0x00, 0x40, 0x14, 0x54 };
  if (row > 3) return;
  lcdCmd(0x80 | base[row]);
  for (uint8_t i = 0; i < LCD_COLS; i++) lcdData(text[i] ? text[i] : ' ');
}
```

## Task 5: The display layer, and the fault row that fixes the architecture

**Files:** Modify `src/ArduinoHydraulicScale.cpp` — `hmiDrawHome`, `hmiDrawMenu`, `hmiDrawCheckCal`, `hmiMessage`, `hmiPoll`

**This task carries the architectural fix**, so read the reason before the code.

The Critical found in the 4-20 mA review was that fault indication lived in `hmiDrawHome()`, and `hmiPoll()` returned early for `SCR_MENU` and `SCR_CHECKCAL` — so **every screen added later silently opted out of it.** A dead transmitter was invisible on the Check-cal screen, and freezing the filter had made that stale reading rock-steady rather than visibly decaying.

- [ ] **Step 1: Replace `lcd` with the new driver**

Delete the `LiquidCrystal lcd(...)` construction and the `pin_RS`/`pin_EN`/`pin_d4..d7`/`pin_BL` constants. Add `#include "lcd2004.h"`. Replace `lcd.begin(16, 2)` in `setup()` with `lcdBegin();`.

- [ ] **Step 2: Add the display-layer render, with row 3 reserved**

```cpp
// Row 3 is the FAULT ROW and belongs to the DISPLAY LAYER, not to any screen.
// It is written on every render regardless of which screen is active, so a
// screen added later CANNOT silently opt out of fault indication the way
// SCR_CHECKCAL did. That was a Critical: a dead transmitter was invisible on
// the calibration-check screen, and the frozen filter made the stale number
// rock-steady rather than visibly decaying -- more convincing, not less.
static void hmiRenderFaultRow() {
  char l3[21];
  if (!loopIsMeasuring(loopState))   snprintf(l3, sizeof(l3), "%-20s", sensorStateName());
  else if (calibrationDefaulted)     snprintf(l3, sizeof(l3), "%-20s", "CAL NOT SET!");
  else if (mcpFailCount() > 0)       snprintf(l3, sizeof(l3), "I2C ERR %-12lu", (unsigned long)mcpFailCount());
  else                               snprintf(l3, sizeof(l3), "%-20s", "");
  lcdLine(3, l3);
}
```

```cpp
// Five buttons to GND on pins freed by the I2C display, read with INPUT_PULLUP.
// Order matches the old ladder exactly: Right, Up, Down, Left, Select.
const uint8_t KEY_PINS[5] = { 4, 5, 6, 7, 8 };

// A LADDER COULD ONLY EVER REPORT ONE KEY -- it is a voltage divider. Discrete
// buttons can be pressed together, and everything downstream assumes "one key or
```
